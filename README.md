# get_2d_cell_from_pdf

Утилиты для получения контуров участков из генплана и сохранения их в `polygon.json`, совместимом с пайплайном `GetCoords/stage1_make_polygon.py`.

Основной рабочий сценарий — прямое извлечение **векторных** контуров из PDF. Он не зависит от разрешения растра и сохраняет исходную геометрию линий. Растровый сценарий сохранён как запасной вариант для PDF без подходящих векторных контуров.

## Возможности

- извлечение замкнутых цветных векторных контуров участков непосредственно из PDF;
- поиск подписи площади внутри каждого контура: значение в сотках переводится в гектары и записывается в поле `size`;
- создание Stage 1 JSON, диагностического JSON и SVG-превью;
- запасное распознавание участков по PNG через OpenCV;
- постобработка топологии растровых контуров: объединение близких вершин и, при необходимости, привязка вершины к соседнему ребру;
- отдельная опция удаления диагональной штриховки в растровом режиме.

## Требования

- Python 3.9+;
- зависимости из `requirements.txt`.

Установка:

```bash
pip install -r requirements.txt
```

Для прямого PDF-экстрактора достаточно Python-зависимостей. Poppler нужен только для старого растрового сценария с `convert_pdf_to_png.py`.

## Основной сценарий: извлечение из PDF

Поместите PDF в папку проекта и запустите:

```bash
python extract_parcels_from_pdf.py "схема раздела 2я страница.pdf"
```

Если путь к PDF не указан, скрипт берёт первый `*.pdf` в текущей папке. По умолчанию обрабатывается первая страница. Для другой страницы:

```bash
python extract_parcels_from_pdf.py plan.pdf --page 2
```

Полный пример с именами результатов:

```bash
python extract_parcels_from_pdf.py plan.pdf --page 1 --dpi 800 --output polygon.json --raw-output pdf_parcels_raw.json --preview pdf_parcels_preview.svg
```

Скрипт ищет замкнутые контуры с бирюзовой, красной, синей или пурпурной линией. Кандидат считается участком, если внутри него найдена подпись формата `N,N` или `NN,NN` — площадь в сотках. Эта подпись переводится в гектары для поля `size`.

### Результаты PDF-экстрактора

| Файл | Назначение |
|---|---|
| `polygon_from_pdf.json` | Основной Stage 1 JSON с контурами и площадью в гектарах |
| `pdf_parcels_raw.json` | Диагностика: исходные координаты PDF, цвет линии, подпись площади и отклонённые контуры |
| `pdf_parcels_preview.svg` | Векторное превью извлечённых участков с исходными подписями в сотках |

Координаты в итоговом JSON масштабируются через `--dpi` (по умолчанию `800`), центрируются относительно страницы и преобразуются в формат `[y, x]`, как ожидает Stage 1.

## Запасной сценарий: распознавание по растру

Используйте его, когда контуры в PDF отсутствуют как отдельные векторные кривые или их цвет не относится к поддерживаемым.

Сначала получите PNG первой страницы:

```bash
python convert_pdf_to_png.py
```

В `convert_pdf_to_png.py` укажите путь к установленному Poppler:

```python
POPLER_BIN = r"C:\tools\poppler-24.08.0\Library\bin"
```

Затем запустите детектор:

```bash
python detect_polygons_from_image.py
```

Он читает `page_1.png` и создаёт:

| Файл | Назначение |
|---|---|
| `output_detected.png` | Цветное превью распознанных участков |
| `polygon_grid.svg` | SVG-сетка распознанных контуров |
| `polygon.json` | Stage 1 JSON |
| `detected_polygons.json` | Сырые пиксельные координаты для диагностики |

### Настройка штриховки и топологии

Параметры находятся в начале `detect_polygons_from_image.py`.

Штриховка по умолчанию не удаляется:

```python
APPLY_HATCH_REMOVAL = False
```

Если диагональная штриховка склеивает или искажает контуры, включите:

```python
APPLY_HATCH_REMOVAL = True
```

Её направление и чувствительность задают `HATCH_ANGLE_DEGREES`, `HATCH_KERNEL_SIZE`, `HATCH_KERNEL_LENGTH`, `HATCH_GRAY_MIN` и `HATCH_GRAY_MAX`. Опцию следует включать только после проверки `output_detected.png`: слишком агрессивная фильтрация может затронуть настоящие границы.

Для выравнивания общих границ доступны две независимые операции:

- `APPLY_VERTEX_SNAP` и `SNAP_TOLERANCE` — схлопывают только близкие вершины разных полигонов;
- `APPLY_EDGE_SNAP` и `EDGE_SNAP_TOLERANCE` — при необходимости вставляют вершину в близкое ребро соседнего полигона; режим сильнее и может ошибочно закрыть реальный зазор.

## Формат результата

Оба основных сценария создают объект следующей структуры. В PDF-сценарии поле `size` заполняется площадью; в растровом сценарии оно остаётся пустым.

```json
{
  "inc": 1,
  "data": [
    {
      "id": 1,
      "idtur": "00001",
      "names": "00001",
      "number": "1",
      "size": "0.12",
      "status": "sale",
      "coordinates": [
        [[y, x], [y, x]]
      ]
    }
  ]
}
```

Остальные обязательные для Stage 1 поля (`adres`, `kadastr`, `price` и другие) также присутствуют и заполняются пустыми строками.

## Вспомогательная утилита

`normalize.py` работает с уже готовыми полигонами: масштабирует и центрирует JSON относительно файла-образца. В основном сценарии обычно не нужен, поскольку оба экстрактора сразу создают совместимый Stage 1 JSON.

Пример:

```bash
python normalize.py --input detected_polygons.json --schema polygon_sample.json --out polygon.normalized.json --auto
```

## Кратко об экспериментах

Старые экспериментальные папки и промежуточные реализации удалены из проекта — в репозитории оставлены только актуальные утилиты. Полезные выводы из экспериментов сохранены в текущем коде:

- растровая бинаризация и поиск контуров OpenCV работают как fallback, но дают границу по краю толщины линии, а не по её оси;
- удаление серых заливок и опциональное удаление штриховки уменьшают ложные склейки;
- vertex/edge snap частично восстанавливают общие границы соседних участков, но требуют осторожной настройки;
- прямое чтение векторных PDF-кривых точнее растрового пути и поэтому является основным методом.

## Ограничения

- PDF-экстрактор рассчитан на цветные замкнутые векторные контуры и подписи площади внутри них; для иной верстки потребуется расширение правил;
- растровый режим чувствителен к качеству исходного изображения и параметрам фильтрации;
- результат предназначен для восстановления визуальной схемы генплана и не заменяет юридически точные кадастровые координаты.
